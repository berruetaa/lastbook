# Interface translations

Setup reads the browser's preferred languages and translates three static labels
using local scripts. English is the fallback. Spanish language tags such as
`es-UY`, `es-AR`, and `es-CL` fall back to `es-419`. The surrounding page
stays English, and translated elements declare their own language.

To add a language, copy the keys in the English catalog in `web/setup-i18n.js`
into a catalog keyed by a BCP 47 tag, such as `fr`. Omitted keys use English.
Use a base-language tag if the catalog should cover regional variants. For a
regional catalog that should serve as a language-wide default, add a fallback
from its base language, as Setup does for Spanish. Keep the existing setup
markers and English HTML text as the baseline when scripts cannot run.

The reusable translator in `web/i18n-core.js` accepts local catalogs. A message
can be a string with named placeholders such as `{name}`, or a plural object
such as `{ one: "{count} file", other: "{count} files" }`. Pass a numeric
`count` for plurals. An optional exact key such as `"=0"` takes precedence over
`Intl.PluralRules`. Render the result using `textContent` to keep translations
and interpolated values as plain text.

Run the offline tests with `node --test app/tests/i18n_core_test.cjs`.
