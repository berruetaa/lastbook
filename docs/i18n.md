# Interface internationalization

Lastbook ships a dependency-free, offline localization engine. The first
preview covers the library's sidebar, tabs, shared navigation and search
controls, plus selected headings and introductory text in Setup and Settings.
English remains the document language. Translated labels carry the language
and direction of the message that actually rendered.

Desktop users can choose **English** or **Español (Latinoamérica)** in first-run
Setup and in **Settings**, which opens **Library and local AI**. Select a
language and press **Save language**. Lastbook applies the new labels in place
after it saves the preference. A failed save keeps the previous language and
announces the failure. The selector describes the Spanish preview's scope.

The rest of the interface, library and search content, source documents, and
model responses are outside this slice. Windows and macOS installers, native
menus and dialogs, and iPad SwiftUI are separate surfaces. The iPad's shared
reader and map pages keep their existing wording and routing. A standalone
browser or LAN client opens in English and has no desktop preference controls.

## Catalogue workflow

1. Edit `translations/desktop/en.json` and `translations/desktop/es-419.json`.
   Use UTF-8 and stable semantic keys such as `nav.guides`. English defines
   the schema. Omit Spanish messages that still need translation.
2. Run `python3 -B packaging/i18n_catalogs.py` and commit both generated
   files, `web/i18n-en.js` and `web/i18n-locales.js`, with the JSON changes.
   The generator emits sorted JSON as data inside flat local scripts.
3. Run the [verification commands](#verification). The standalone checker
   and desktop staging reject absent or stale generated files.

Values are nonempty strings or plural objects with an `other` form. Named
placeholders use `{name}` with an ASCII letter or underscore first. A
translation keeps the same placeholders and message type as English. Plural
objects may use different language-specific categories. They keep English's
exact selectors, such as `=0`, and the same non-count placeholders in every
form. `{count}` can be omitted from an individual form. Exact selectors are
nonnegative safe integers. The generator rejects duplicate keys at any depth,
unknown messages, invalid Unicode or value types, and incompatible contracts.

Add catalogue files under canonical locale names. To expose another choice,
update the web controller, desktop preference allowlist and selector together.
Add any regional inheritance explicitly, with tests. The engine can take
routes from `es-AR`, `es-CL` and `es-UY` to `es-419` in its `fallbacks` option.
The selector and preference file accept `en` and `es-419`. In engine lookups
Spanish from Spain, bare `es` and other undeclared variants fall back to
English, and English variants inherit `en`.

## Runtime and bindings

- `web/i18n-core.js` validates and copies the catalogue, negotiates locale tags
  with `Intl`, and resolves messages to plaintext and the catalogue language.
  `t(key, params)` returns plaintext. `resolve(key, params)` also gives its
  locale. Both return `undefined` for unknown keys.
- Message lookup tries the exact tag, explicit inheritance, and ordinary
  locale ancestry before the English fallback. A Unicode extension such as
  `-u-nu-arab` affects formatting while message selection can use the base
  tag. The engine can negotiate a caller-supplied list of preferences.
  Lastbook starts in English and activates Spanish only from a saved choice
  or a successful explicit save. It does not consult browser language settings.
- `number` and `date` use the formatting locale. Plural category selection
  uses the message's language, and `{count}` uses the formatting locale.
  Both round to at most three fractional digits. Interpolation accepts own
  primitive values and isolates substituted text in RTL messages. Language
  selection does not change measurement units or system language preferences.
- `web/i18n-dom.js` binds marked leaf text with `data-i18n`. Keep the
  English text in markup so it remains readable if scripts fail. Put a
  marker on a child span in controls that contain icons. Attribute markers
  cover `aria-label`, `placeholder`, `title` and `alt`. A container can
  opt in to the bound label's language with `data-i18n-lang` when its
  descendants share that language or are decorative.
- Use `LastbookI18n?.apply(container)` after explicitly rendering marked
  interface elements. To supply parameters, pass a function of the element
  and message key as the second argument. The adapter uses text and attribute
  setters and retains the provider only for that element and key. Leave
  unmarked data, links, and HTML sinks outside the translation path.
- `web/i18n-app.js` starts the shared policy for the two entry points. It
  reapplies the bindings on a saved change. Setup keeps the selector outside
  the changing view, and the library updates compact tooltips and responsive
  placeholders without rebuilding the page.

## Preference and packaging

The socket-free desktop bridge exposes `GET`, `HEAD` and `POST /api/ui-language`
to its authenticated top frame. The read returns the stored choice or null.
The write accepts one JSON property, `language`, set to a supported tag.
All three methods require the launch key. The ordinary HTTP handler has no route
for this preference. Responses are not cached.

The app stores `ui-language.json` alongside its settings under
`%APPDATA%\Lastbook` (Windows), `~/Library/Application Support/Lastbook`
(macOS), or `$XDG_CONFIG_HOME/Lastbook` (Linux, normally
`~/.config/Lastbook`). The file is independent of `settings.json`, the
library path and WebView storage. Each write creates and flushes a unique
temporary file in the settings directory before atomically replacing the
published file. The last successful replacement wins across windows.
Reads use the published file. An interrupted process can leave a temporary
file, which readers ignore. A handled write failure leaves the published
file intact and attempts to remove its own temporary file.

Settings finishes its initial read before accepting a save and allows one
save at a time per document. Each window shows its own acknowledged choice.
The library refreshes when restored from the back-forward cache and ignores
older overlapping read replies. Other open windows read the current choice
on their next load. A missing or invalid preference uses English. If Spanish
assets fail, the app uses English and retains the saved Spanish choice for
the next successful load.

All desktop builds stage the same flat assets with `ship_app_files.py`.
The build checks the Windows distribution, Windows installer input, macOS
resources and the extracted Linux package. Native apps serve the assets
from their installed files. The localhost service worker also caches the
library shell's localization scripts for an offline reload. No translation
fetch, translation service, new host, or manifest-refresh change is needed.

## Verification

```bash
python3 -I -B packaging/i18n_catalogs.py --check
python3 -B -m unittest app.tests.test_i18n_catalogs app.tests.test_bridge
node --test app/tests/i18n_core_test.cjs
python3 -B app/tests/i18n_browser.py --chromium /path/to/chromium
```

The browser check uses optional Playwright development tooling and an installed
Chromium build. It exercises the staged UI through the real bridge and HTTP
handlers with a test-only loopback relay. Run the full contributor suite as
well. [Contributor test commands](../CONTRIBUTING.md#test)

On Ubuntu, the installed package can be exercised in an isolated X11 and
D-Bus session with `app/tests/linux_i18n_smoke.py`. The script uses AT-SPI
and `xdotool` to save a language, complete Setup, reopen with a fresh profile
and different library, and switch back to English in Settings.

For a release, build and scan each platform's package. In the native app
start with a fresh settings and WebView profile, save Spanish in Setup, and
complete Setup with a fixture library. Reopen the installed app, change
libraries, and verify Spanish in the sidebar, tabs and Settings. Switch to
English and check keyboard focus, spoken labels, and the preview notice.
Run these checks offline using a local library. For Windows also check the
installed app launched by the installer. [Build commands](../README.md#build-the-apps)
